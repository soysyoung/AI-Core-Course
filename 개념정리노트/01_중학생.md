## Day6 (10/26) · 머신러닝 첫걸음 — 회귀와 분류

| 용어 | 쉬운 설명 |
|---|---|
| 머신러닝 | 정답이 있는 예시를 많이 보여 주면 컴퓨터가 스스로 규칙을 찾아내는 방법 |
| 특성(Feature) | 답을 맞힐 때 참고하는 정보 (예: 글자 수, 작업 종류) |
| 정답(Label/Target) | 컴퓨터가 맞혀야 하는 값 (예: 실패했는지, 걸린 시간) |
| 학습(fit) | 예시를 보면서 규칙을 찾는 과정 |
| 예측(predict) | 찾은 규칙으로 처음 보는 문제의 답을 내는 것 |
| 회귀 | 숫자(시간, 가격 등)를 맞히는 문제 |
| 분류 | 정해진 종류 중 하나(성공/실패)를 고르는 문제 |
| 선형회귀 | 점들 사이를 가장 잘 지나가는 직선을 그어서 숫자를 예측하는 방법 |
| 오차 | 예측한 값과 진짜 값의 차이 |
| MAE | 틀린 크기를 그냥 평균 낸 점수 (작을수록 좋음) |
| MSE | 틀린 크기를 제곱해서 평균 낸 점수, 크게 틀린 것을 더 혼냄 |
| 로지스틱 회귀 | 이름은 회귀지만 "실패할 확률"을 계산해서 분류하는 방법 |
| 임계값 | 확률이 이 기준(예: 0.5)을 넘으면 "실패"라고 판정하는 선 |
| KNN | 나와 가장 가까운 이웃 K개에게 물어보고 다수결로 정하는 방법 |
| K | 이웃을 몇 명까지 물어볼지 정하는 숫자 |
| 스케일링 | 단위가 다른 숫자들(글자 수 vs 0/1)을 비슷한 크기로 맞춰 공정하게 비교하는 것 |
| train / valid / test | 공부용 / 연습시험용 / 실전시험용으로 데이터를 나눈 것 |
| 데이터 누수 | 실전시험 문제를 미리 보고 공부한 것처럼, test 정보가 학습에 섞여 들어간 실수 |

## Day7 (10/27) · 나무 모델 — Decision Tree · Random Forest · XGBoost

| 용어 | 쉬운 설명 |
|---|---|
| 결정 트리 | 스무고개처럼 예/아니오 질문을 이어 가며 답을 찾는 모델 |
| 깊이(depth) | 스무고개에서 질문을 최대 몇 번까지 할 수 있는지 |
| 잎(leaf) | 질문이 끝나서 답이 정해지는 마지막 칸 |
| 과적합 | 연습문제 답만 통째로 외워서 새 문제는 못 푸는 상태 |
| 과소적합 | 너무 대충 공부해서 연습문제조차 못 푸는 상태 |
| 랜덤 포레스트 | 조금씩 다르게 자란 나무 여러 그루에게 물어보고 다수결로 정하는 모델 |
| 앙상블 | 여러 모델의 답을 모아 더 믿을 만한 답을 만드는 방법 |
| XGBoost (부스팅) | 앞 나무가 틀린 부분을 다음 나무가 보충하며 차례로 쌓아 가는 모델 |
| 특성 중요도 | 어떤 정보가 답을 정할 때 많이 쓰였는지 매긴 점수 |
| 순열 중요도 | 한 정보를 일부러 뒤섞었을 때 성적이 얼마나 떨어지는지로 중요도를 재는 방법 |
| 교차검증(CV) | 데이터를 여러 조각으로 나눠 돌아가며 시험 보고 평균 점수를 내는 방법 |
| 원핫 인코딩 | "qa", "summary" 같은 글자 종류를 0과 1로 된 칸으로 바꿔 컴퓨터가 읽게 하는 것 |
| 결측값 대체 | 비어 있는 칸을 평균 같은 값으로 채워 넣는 것 |
| Pipeline | 전처리 → 모델 순서를 한 줄로 묶어서 순서가 섞이지 않게 하는 것 |
| seed (재현성) | 무작위를 고정해서 다시 실행해도 똑같은 결과가 나오게 하는 번호 |

## Day8 (10/28) · 평가지표와 군집

| 용어 | 쉬운 설명 |
|---|---|
| 혼동행렬 | 맞힌 것과 틀린 것을 4칸 표로 정리한 성적표 |
| 정확도(Accuracy) | 전체 문제 중 맞힌 비율 |
| 정밀도(Precision) | "실패"라고 말한 것 중에서 진짜 실패였던 비율 |
| 재현율(Recall) | 진짜 실패들 중에서 놓치지 않고 찾아낸 비율 |
| F1 | 정밀도와 재현율을 함께 고려한 균형 점수 |
| ROC 곡선 | 판정 기준선을 바꿔 가며 실패를 얼마나 잘 골라내는지 그린 그래프 |
| AUC | ROC 곡선 아래 넓이, 1에 가까울수록 잘 구별함 (판정값이 아닌 확률로 계산) |
| RMSE | 오차를 제곱 평균한 뒤 루트를 씌워 "원래 단위로 평균 얼마나 틀렸나"를 나타낸 값 |
| 비지도 학습 | 정답 없이 데이터끼리 비슷한 것을 묶는 학습 |
| K-Means 군집 | 데이터를 K개의 무리로 나누고 무리마다 중심점을 찾는 방법 |
| 군집 번호 | 무리에 붙인 이름표일 뿐, 숫자가 크다고 더 위험하다는 뜻이 아님 |
| 평가 계획 | 시험 보기 전에 어떤 점수로 비교할지 미리 정해 두는 것 (결과 보고 바꾸지 않기) |

## Day9 (10/29) · 딥러닝 기초 — GPU · Tensor · Autograd · ANN

| 용어 | 쉬운 설명 |
|---|---|
| GPU | 단순한 계산을 한꺼번에 아주 많이 처리하는 그래픽카드 |
| CUDA | 파이썬 프로그램이 GPU를 쓸 수 있게 해 주는 도구 |
| PyTorch | 딥러닝 모델을 만들고 학습시키는 파이썬 도구 모음 |
| Tensor | 숫자를 여러 겹으로 담는 상자 (표를 여러 장 쌓은 것) |
| shape | 텐서 상자의 가로·세로·깊이 크기 |
| device | 계산을 CPU에서 할지 GPU에서 할지 정하는 자리 |
| 기울기(Gradient) | 값을 조금 바꿨을 때 결과가 얼마나, 어느 방향으로 변하는지 |
| Autograd | 기울기를 자동으로 계산해 주는 PyTorch 기능 |
| 경사하강법 | 오차가 줄어드는 방향으로 한 걸음씩 내려가며 값을 고치는 방법 |
| 학습률 | 한 걸음을 얼마나 크게 내디딜지 정하는 값 |
| 인공신경망(ANN) | 뇌의 뉴런처럼 연결된 계산 층을 여러 개 쌓은 모델 |
| 가중치 / 편향 | 신경망이 학습하면서 스스로 고쳐 나가는 숫자들 |
| 활성화 함수(ReLU) | 음수는 0으로 바꿔서 직선이 아닌 복잡한 모양도 배우게 해 주는 장치 |
| 손실 함수 | 모델이 얼마나 틀렸는지를 하나의 점수로 계산하는 식 |
| 배치 | 데이터를 한 번에 몇 개씩 묶어서 학습하는 단위 |
| 에폭(Epoch) | 전체 데이터를 한 바퀴 다 학습한 횟수 |
| 학습 루프 | 예측 → 손실 계산 → 기울기 계산 → 가중치 수정을 반복하는 과정 |
| 체크포인트 | 학습 중간 상태를 저장해 두었다가 나중에 이어서 하는 것 |

## Day10 (10/30) · 학습 안정화

| 용어 | 쉬운 설명 |
|---|---|
| 옵티마이저 | 가중치를 어떤 방식으로 고칠지 정하는 규칙 (SGD, Adam 등) |
| 모멘텀 | 굴러가는 공처럼 이전 방향의 힘을 이어받아 더 매끄럽게 내려가는 방법 |
| 학습 곡선 | 에폭마다 손실이 어떻게 변하는지 그린 그래프 |
| 배치 크기 | 한 번에 묶는 데이터 수, 너무 작으면 들쭉날쭉하고 너무 크면 느리게 배움 |
| 모델 너비 | 한 층에 뉴런이 몇 개 있는지 |
| 드롭아웃 | 학습 때 뉴런 일부를 일부러 쉬게 해서 답을 통째로 외우지 못하게 하는 방법 |
| 배치 정규화 | 층마다 숫자 크기를 고르게 맞춰 학습을 안정시키는 방법 |
| train 모드 / eval 모드 | 드롭아웃 등은 공부할 때와 시험 볼 때 다르게 동작해서 스위치를 바꿔 줘야 함 |
| 최적 상태 복원 | 학습 중 valid 점수가 가장 좋았던 순간의 모델로 되돌리는 것 |

## Day11 (11/2) · CNN · 이미지 분류 · 전이학습

| 용어 | 쉬운 설명 |
|---|---|
| 이미지 텐서 | 사진을 색(RGB 3장) × 세로 × 가로 숫자 상자로 바꾼 것 |
| 합성곱(Convolution) | 작은 돋보기(필터)를 사진 위로 밀면서 무늬를 찾아내는 계산 |
| 필터(커널) | 특정 무늬(가로줄, 세로줄 등)에 반응하는 작은 숫자 판 |
| 채널 | 한 사진에 겹쳐 있는 정보 장 수 (컬러는 3장, 필터를 지나면 더 늘어남) |
| 풀링 | 작은 구역에서 대표값(가장 큰 값)만 남겨 사진 크기를 줄이는 것 |
| CNN | 합성곱과 풀링을 쌓아 사진을 이해하는 신경망 |
| ImageFolder | 폴더 이름을 정답으로 삼아 사진을 읽어 오는 방식 |
| 데이터 증강 | 사진을 뒤집거나 살짝 돌려서 연습문제 수를 늘리는 방법 |
| 전이학습 | 다른 큰 데이터로 이미 공부한 모델을 가져와 내 문제에 맞게 조금만 더 가르치는 것 |
| 사전학습 가중치 | 큰 데이터(ImageNet)로 미리 학습해 둔 모델의 숫자들 (예: ResNet18) |
| 동결(Freeze) | 가져온 모델의 앞부분은 고치지 못하게 잠가 두는 것 |
| 벤치마크 | 모델이 얼마나 빠르고 메모리를 얼마나 쓰는지 재는 것 |

## Day12 (11/3) · 순서가 있는 데이터 — RNN · LSTM · Attention

| 용어 | 쉬운 설명 |
|---|---|
| 시퀀스 | 순서가 중요한 데이터 (문장, 시간별 기록) |
| 시계열 | 시간 순서대로 쌓인 숫자 기록 |
| Window | 연속된 몇 칸을 잘라서 하나의 문제로 만든 것 |
| 시간순 분할 | 미래 정보로 과거를 맞히지 않도록 시간 순서대로 train/valid/test를 나누는 것 |
| Padding | 길이가 다른 문장을 같은 길이로 맞추려고 빈칸(0)을 채우는 것 |
| 마스크 | 채운 빈칸은 보지 말라고 가려 주는 표시 |
| RNN | 앞에서 읽은 내용을 기억하며 한 칸씩 읽어 나가는 모델 |
| LSTM | 중요한 건 오래 기억하고 필요 없는 건 잊는 "문"이 달린 RNN |
| Autoencoder | 입력을 꾹 압축했다가 다시 복원하면서 핵심만 배우는 모델 |
| 재구성 오차 / 이상탐지 | 복원이 잘 안 되면 평소와 다른 "이상한" 데이터로 판단하는 방법 |
| Attention | 전체 중에서 지금 중요한 부분에 더 집중하도록 점수를 주는 방법 |

## Day13 (11/4) · OpenCV 이미지·영상 전처리

| 용어 | 쉬운 설명 |
|---|---|
| OpenCV | 사진과 영상을 다루는 기능을 모아 둔 도구 |
| 픽셀 | 사진을 이루는 아주 작은 점 하나 |
| BGR | OpenCV가 색을 파랑-초록-빨강 순서로 읽는 방식 (보통은 RGB) |
| 그레이스케일 | 색을 빼고 밝기만 남긴 흑백 사진 |
| 리사이즈 | 사진 크기를 늘리거나 줄이는 것 |
| 블러(필터) | 주변 픽셀과 평균 내서 흐리게 만들어 잡티를 줄이는 것 |
| 엣지 검출(Canny) | 밝기가 확 바뀌는 경계선을 찾아내는 방법 |
| 이진화(Threshold) | 기준보다 밝으면 흰색, 아니면 검은색으로 나누는 것 |
| 모폴로지 | 흰 영역을 깎거나(침식) 불려서(팽창) 작은 잡티를 없애거나 구멍을 메우는 것 |
| 프레임 / FPS | 영상은 사진(프레임)을 빠르게 넘긴 것, FPS는 1초에 넘기는 장 수 |

## Day14 (11/5) · 전이학습 심화와 오류 분석

| 용어 | 쉬운 설명 |
|---|---|
| Dataset / DataLoader | 데이터를 하나씩 꺼내 주는 창고 / 배치로 묶어 날라 주는 운반차 |
| 헤드(Head) | 모델 맨 끝에서 최종 답을 고르는 부분, 내 문제에 맞게 갈아 끼움 |
| 파인튜닝 | 가져온 모델의 잠금을 일부 풀고 내 데이터로 살짝 더 학습시키는 것 |
| 클래스 불균형 | 한 종류 데이터만 지나치게 많은 상황 |
| 가중 손실 | 수가 적은 종류를 틀리면 벌점을 더 크게 줘서 균형을 맞추는 방법 |

## Day28 (11/25) · RAG 평가

| 용어 | 쉬운 설명 |
|---|---|
| Gold 데이터셋 | 질문마다 "이 문서가 정답 근거"라고 미리 정해 둔 채점용 정답지 |
| 무정답 질문(No-answer) | 문서 안에 답이 아예 없는 질문, AI가 "모른다"고 해야 정답 |
| Recall@k | 정답 문서들 중 상위 k개 검색 결과 안에 들어온 비율 |
| Precision@k | 상위 k개 검색 결과 중 정답 문서의 비율 |
| 순위 지표(MRR·nDCG) | 정답 문서가 얼마나 앞쪽 순서에 나왔는지까지 따지는 점수 |
| Claim | AI 답변을 사실 하나하나로 쪼갠 문장 |
| 근거 일치 | 각 Claim이 찾아온 문서에 실제로 적혀 있는지 확인하는 것 |
| 질문 적합성 / 정답성 | 질문에 맞는 답을 했는지 / 그 답이 사실로 맞는지 |
| Target / Evaluator | 시험 보는 쪽(RAG) / 채점하는 쪽, 정답지는 채점하는 쪽만 봄 |
| 한 번에 하나만 바꾸기 | 여러 개를 동시에 바꾸면 무엇 때문에 좋아졌는지 모르니 하나씩 바꿔 비교하는 것 |
| 오프라인 / 라이브 | 미리 저장된 고정 결과로 연습 / 실제 모델·DB를 호출해서 실행 |
| 실패 단계 진단 | 틀린 답이 고장·검색·Context·답변 생성 중 어느 단계에서 생겼는지 차례로 찾아내는 것 |
| invoke | 미리 만들어 둔 체인(Runnable)을 실제로 실행시키는 버튼 |
| 4가지 비교군 | 기본 / 질문 고쳐쓰기만 / 리랭커만 / 둘 다, 네 가지를 같은 정답지로 채점해 비교하는 것 |
| 배포 보류(회귀 판정) | 새 버전이 예전보다 점수가 떨어지면 내보내지 않고 멈추는 규칙 |
| Agent 1차 관문 | 검색 점수·출처·사람 검토·접근 제한을 모두 확인한 뒤에야 Agent 도구로 쓸 준비가 됐다고 보는 첫 번째 검사 |
