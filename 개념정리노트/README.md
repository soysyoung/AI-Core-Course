# 개념정리노트

`practice_assignment` 실습 자료에서 배운 개념을 **같은 용어 목록**으로 단계별로 정리합니다.
한 단계가 이해되면 다음 단계로 넘어갑니다.

## 단계 구성

| 단계 | 파일 | 답하는 질문 | 추가되는 것 | 분량 |
|---|---|---|---|---|
| 1. 중학생 | [01_중학생.md](01_중학생.md) | **무엇인가?** | 비유 | 1줄 |
| 2. 고등 | [02_고등.md](02_고등.md) | **어떻게 계산하나?** | 간단한 수식, 작은 숫자 예시 | 2~3줄 |
| 3. 대학 | `03_대학.md` (예정) | **왜 이 방법이고, 무엇과 맞바꾸나?** | 정확한 정의, 비슷한 개념과의 비교, 장단점 | 짧은 단락 |
| 4. 신규입사자 | `04_신규입사자.md` (예정) | **실제로 어떻게 쓰고, 어디서 실수하나?** | 코드 API, 흔한 실수, 실습 파일 위치, 판단 기준 | 카드 형식 |

## 예시: 재현율(Recall) 한 용어를 네 단계로

- **중학생**: 진짜 실패들 중에서 놓치지 않고 찾아낸 비율
- **고등**: 재현율 = 찾아낸 실패 ÷ 진짜 실패 전체. 실패 4건 중 3건을 잡으면 0.75. 놓치면 큰일 나는 문제(병 진단)에서 특히 중요하다.
- **대학**: TP / (TP + FN). 정밀도와 맞바꾸는 관계로, 임계값을 낮추면 재현율↑ 정밀도↓. F1은 둘의 조화평균. 양성이 드문 데이터에서는 정확도보다 의미 있다.
- **신규입사자**: `recall_score(y_true, y_pred)`에는 확률이 아니라 판정값(0/1)을 넣는다. `pos_label`을 확인하고, 양성 0건이면 값이 0이 되는 점에 주의한다. 임계값은 놓쳤을 때의 비용을 기준으로 valid에서 정하고 test는 한 번만 확인한다. 보고할 때는 혼동행렬을 함께 붙인다.

## 작성 규칙

1. **용어 목록과 순서는 모든 단계에서 같게** 유지합니다. 단계별 파일을 나란히 놓고 비교할 수 있게 하기 위해서입니다.
2. 단계가 올라가면 **모든 용어를 늘리지 않습니다.** 충분히 이해된 기초 용어(GPU, 픽셀 등)는 해당 단계에서 끝냅니다.
3. 신규입사자 단계는 날짜별이 아니라 **업무 흐름별**("모델 평가하기", "RAG 품질 개선하기")로 묶습니다.
4. 각 단계 끝에 "보지 않고 설명해 보기" 질문을 두고, 막히는 용어만 다음 단계로 넘깁니다.

## 새 날짜 추가하는 법

`practice_assignment`에 날짜 폴더가 새로 생기면 각 단계 파일의 **맨 아래에 이어서** 추가합니다.
공통 원칙과 큰 그림은 파일 위쪽에 있어서 이어 붙여도 순서가 섞이지 않습니다.

1. 새 폴더의 `README.md`와 실습 폴더/파일 이름을 보고 그날의 주제와 용어를 뽑습니다.
2. 각 단계 파일 맨 아래에 `## DayN (MM/DD) · 주제` 섹션을 같은 표 형식으로 추가합니다.
3. 필요하면 위쪽의 "큰 그림"과 아래 "포함 범위" 표를 갱신합니다.

Claude에게 맡길 때 예시: `practice_assignment의 20261126 폴더로 개념정리노트 모든 단계에 새 날짜 추가해줘`
