# 쉽게 보는 01_basic 안내서

> 이 문서는 초등~중학생을 위한 설명이에요. 실제 과제 안내는 `README.md`와 각 폴더의 `README.md`를 보세요.

## 1. 이 과제는 무엇인가요?

**"AI에게 질문하고, 믿을 수 있는 답을 받는 방법"을 연습하는 과제**예요.

AI는 가끔 **모르는 것도 아는 척** 대답해요. 그래서 이 과제에서는 이런 것들을 배워요.

- AI에게 **어떻게 부탁해야** 하는지
- AI에게 **어떤 자료를 줘야** 하는지
- AI가 **모르면 "모르겠어요"라고 말하게** 하는 방법
- AI의 답이 **약속한 모양인지 검사**하는 방법
- 틀렸을 때 **딱 한 번만 다시** 시키는 방법

> 중요한 점: 이 과제에서는 **진짜 AI를 호출하지 않아요.**
> AI에게 줄 **부탁 글을 만들고**, 답을 **검사하는 도구**를 만드는 연습이에요.

### 비유로 이해하기
**도서관 사서 로봇**을 떠올려 보세요.
- 손님이 질문하면 로봇이 **자료(책)를 찾아서** 답해요.
- 책에 없는 내용은 **"책에 없어요"라고** 말해야 해요.
- 답할 때는 **어느 책을 봤는지(출처 번호)** 도 같이 말해야 해요.

이 로봇이 믿을 만하게 일하도록 **규칙을 정하고 시험해 보는 것**이 이 과제예요.

---

## 2. 전체 흐름 (8단계)

```
[1 부탁 글 만들기] → [2 예제 보여주기] → [3 모르는 것 찾기] → [4 자료 고르기]
        ↓
[8 마지막 시험 준비] ← [7 틀리면 한 번만 다시] ← [6 답 검사하기] ← [5 A/B 비교하기]
```

크게 4덩어리로 나눌 수 있어요.

| 덩어리 | 단계 | 한 줄 설명 |
|---|---|---|
| **준비하기** | 01, 02 | 부탁 글을 만들고 예제를 보여 줘요 |
| **자료 다루기** | 03, 04 | 모르는 것을 찾고, 줄 자료를 골라요 |
| **비교·검사하기** | 05, 06 | 두 방법을 비교하고, 답을 검사해요 |
| **마무리** | 07, 08 | 다시 시키는 규칙을 만들고 전체를 이어요 |

---

## 3. 단계별 설명과 핵심 키워드

### 01. 부탁 글의 뼈대 (`01_prompt_structure`)
**하는 일:** AI에게 줄 부탁 글(프롬프트)에 꼭 들어갈 **여섯 칸**을 채워요.

| 칸 | 뜻 | 심부름 비유 |
|---|---|---|
| 역할 | 누구로서 일하나 | "너는 도우미야" |
| 작업 | 무엇을 하나 | "질문에 답해 줘" |
| 입력 | 무엇을 가지고 하나 | "이 자료를 보고" |
| 제약 | 하면 안 되는 것 | "자료에 없는 건 쓰지 마" |
| 실패 | 못하면 어떻게 하나 | "모르면 모른다고 해" |
| 출력 | 결과는 어떤 모양인가 | "이 양식으로 적어" |

**핵심 키워드:** `프롬프트` `여섯 칸` `Template(빈칸 양식)` `요구사항`

---

### 02. 예제 보여주기 (`02_examples_versions`)
**하는 일:** AI에게 **예제를 보여 주는 방법**과 **안 보여 주는 방법**을 만들어요.

- **Zero-shot:** 예제 없이 바로 질문해요. (설명 없이 문제부터 푸는 것)
- **Few-shot:** 예제 몇 개를 먼저 보여 줘요. (풀이 예시를 보고 푸는 것)
- 예제는 **잘 답한 것 하나**와 **"모르겠다"고 한 것 하나**를 써요.

**핵심 키워드:** `Zero-shot` `Few-shot` `예제` `버전` `한 번에 하나만 바꾸기`

---

### 03. 모르는 것 찾기 (`03_task_decomposition`)
**하는 일:** 질문에 답하려면 **꼭 필요한 사실**이 뭔지 나누고, **자료에 없는 사실**을 찾아요.

- 질문 → 필요한 사실 목록 → 우리 자료에 있나? → 없으면 **"자료 부족"**
- 하나라도 모르면 **반쪽짜리 답을 하지 않고** 멈춰요.

> 비유: 친구 숙제 목록과 내 준비물을 비교해서 **빠진 것**을 찾는 거예요.

**핵심 키워드:** `작업 분해` `필요한 사실` `missing(빠진 것)` `정보 부족` `추측하지 않기`

---

### 04. 자료 고르기와 예산 (`04_context_builder`)
**하는 일:** AI에게 줄 **자료를 번호로 골라서** 글로 만들고, **자리가 얼마나 남는지** 계산해요.

- 고른 번호 **순서를 지켜서** 자료를 꺼내요.
- 없는 번호를 고르면 **오류**를 내요.
- **빼 버린 자료와 그 이유**도 적어 둬요.
- 계산: `8192 − 800 − 600 − 1600 − 256 = 4936` (가상의 숫자예요)

> 비유: 가방(8192칸)에 **꼭 챙길 것을 먼저 넣고**, 남는 자리에 자료를 넣는 거예요.

**핵심 키워드:** `Context(자료)` `ID 선택` `예산(token)` `포함/제외` `JSON`

---

### 05. A/B 비교 (`05_ab_evaluation`)
**하는 일:** 부탁 글을 **A와 B 두 가지**로 만들어서 **어느 쪽이 나은지 비교할 준비**를 해요.

- B에는 **규칙 한 줄만 더** 넣고, 나머지는 **모두 똑같이** 해요.
- 연습 문제 D01~D03 세 개 × A/B = **첫 응답 6개**
- **첫 번째 시도만** 세요. "아직 안 한 것"을 0점으로 바꾸지 않아요.

> 비유: 달리기 기록을 재는데 **신발만 바꿔 신고** 나머지는 같게 하는 거예요.

**핵심 키워드:** `A/B 비교` `딱 하나만 바꾸기` `첫 응답` `미실행` `미평가(None)`

---

### 06. 답 검사하기 (`06_output_validation`)
**하는 일:** AI의 답이 **약속한 양식**인지 검사하는 **접수 선생님**을 만들어요.

검사는 3단계예요.
1. **글을 읽을 수 있나?** 괄호가 빠져 깨졌으면 → `json_error`
2. **양식이 맞나?** 숫자 자리에 글자("101")가 있으면 → `schema_error`
3. **말이 앞뒤가 맞나?** 준 자료에 없는 번호(예: 999)를 댔으면 → `unknown_source`

> 한계: **번호가 맞는지**만 봐요. 답 **내용이 진짜 맞는지**는 사람이 읽어야 해요.

**핵심 키워드:** `JSON` `Schema(양식)` `검증` `출처 번호` `오류 이름 나누기`

---

### 07. 틀리면 딱 한 번만 다시 (`07_bounded_retry`)
**하는 일:** 답이 틀렸을 때 **다시 고쳐 쓰게 하는 규칙**을 만들어요.

- 처음 1번 + 고쳐서 1번 = **최대 2번**이에요.
- **형식이 틀린 것만** 다시 시켜요. 가짜 출처를 댄 건 바로 멈춰요.
- 다시 시킬 때는 **짧은 한 문장**으로만 알려 줘요. (이전 답 전체나 비밀 정보는 붙이지 않아요)
- 연습 결과의 호출 횟수는 **2, 2, 1, 1**이 나와야 해요.

> 비유: 숙제에 **한 번만 고쳐 올 기회**를 주는 거예요. 끝없이 고치게 하지 않아요.

**핵심 키워드:** `재시도` `최대 2회` `형식 오류` `수정 요청` `무한 반복 막기`

---

### 08. 마지막 프로젝트 (`08_daily_project`)
**하는 일:** 지금까지 만든 것을 **하나로 이어서**, 진짜 시험 문제(H01~H03)로 쓸 **시험지와 채점표**를 준비해요.

- 05번에서 **고정해 둔 A/B 묶음**을 그대로 가져와요.
- 시험 문제 3개 × A/B = 첫 응답 **6개**
- 결과표에서 **"아직 안 했음"을 그대로** 보여 줘요. "B가 이겼다"고 미리 쓰지 않아요.

> 비유: 연습 문제로 공부한 뒤 **기말고사를 준비**하는 거예요.

**핵심 키워드:** `holdout(시험용 문제)` `프로젝트` `미실행/미평가` `승자 정하지 않기`

---

## 4. 단계별 한눈에 보기

| 단계 | 폴더 | 한 줄 | 핵심 키워드 |
|---|---|---|---|
| 01 | `01_prompt_structure` | 부탁 글의 여섯 칸 만들기 | 프롬프트, 여섯 칸 |
| 02 | `02_examples_versions` | 예제 있는/없는 부탁 글 | Zero-shot, Few-shot |
| 03 | `03_task_decomposition` | 모르는 것 찾아 멈추기 | 정보 부족, 추측 금지 |
| 04 | `04_context_builder` | 자료 고르기와 자리 계산 | Context, 예산 |
| 05 | `05_ab_evaluation` | 두 방법 공정하게 비교 | A/B, 하나만 바꾸기 |
| 06 | `06_output_validation` | 답의 양식 검사 | JSON, Schema, 출처 |
| 07 | `07_bounded_retry` | 최대 한 번만 다시 시키기 | 재시도, 최대 2회 |
| 08 | `08_daily_project` | 전체를 잇는 마무리 | holdout, 미평가 |

---

## 5. 꼭 기억할 3가지

1. **모르면 모른다고 말하게 하기** — 아는 척하는 것보다 안전해요.
2. **비교할 때는 하나만 바꾸기** — 그래야 무엇 때문인지 알 수 있어요.
3. **"통과"는 "훌륭하다"가 아니에요** — 양식이 맞다는 뜻일 뿐, 내용이 맞는지는 사람이 확인해야 해요.

## 6. 이 과제가 알려 주지 못하는 것

- **진짜 AI가 얼마나 잘하는지**는 몰라요. 가짜 연습 답으로 **흐름만** 확인해요.
- 05번과 08번은 AI의 답을 **직접 받아서 넣기 전에는** 모든 칸이 "아직 안 함"이에요. 이건 0점이 아니에요.

## 7. 실행하는 방법

각 폴더로 들어가서 아래처럼 실행해요.

```powershell
python main.py
```

05번과 08번만 명령이 여러 개예요.

```powershell
python main.py prepare   # 시험지 준비
python main.py fixtures  # 가짜 답으로 흐름 확인
python main.py review    # 결과 정리
```
